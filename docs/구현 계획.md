## 8. 사람이 해야 하는 일

Claude가 대신하지 않는 일임. 키와 비밀번호 입력, 계정 설정, 제출은 사용자가 직접 함.

| 때 | 일 |
|---|---|
| 배포 전 | GitHub 저장소 만들기(비공개), Streamlit Workspace에서 비공개 저장소 읽기 허용(D2) |
| 배포 | Streamlit Secrets에 `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`를 `이름 = "값"` 꼴로 입력(D2). 브라우저 자동 완성이 예전 값을 채울 수 있으므로 지우고 다시 씀 |
| 배포 | 앱 공유 설정을 "This app is public and searchable"로 저장(D3) |
| keepalive | GitHub 저장소의 Secrets에 `DATABASE_URL` 등록(T1.6, D5) |
| 제출 | e-class에 제출(D8), 11/3 09:00 전 저장소 공개(D9) |
| 커밋 | 지금까지 커밋은 사용자가 정한 시점에 함. 이 계획은 커밋을 하지 않음 |

## 9. 위험과 대응

| 번호 | 위험 | 대응 |
|---|---|---|
| 1 | 설치한 Streamlit 판에서 `st.container(key=)`가 동작하지 않음 | T0.5에서 확인함. 안 되면 판을 올리거나, 공고 2.7절의 key 방식에 맞는 요소로 바꾸고 신 교수에게 확인함 |
| 2 | fragment 자동 갱신이 AI 배정 실행을 끊음 | PRD_step3 6장(AI 대기 중 화면)의 우회 방식과 90초 가짜 느린 호출 시험(T3.3). 그래도 끊기면 배정 실행을 별도 스레드와 DB 상태 확인 방식으로 바꿈 |
| 3 | 무료 모델이 채점 때 모두 실패함 | 3차까지 실패하면 앱이 직접 배정함(PRD_step3 5.6절, 3차까지 실패). 모델 순서는 T3.4의 측정으로 조정 |
| 4 | 무료 모델의 하루 한도 소진 | 개발 중 하루 20회 이하, 채점 기간 시험 금지(PRD_step3 5.7절, 호출 한도) |
| 5 | 연결 풀러(6543)에서 준비된 문장 때문에 오류 | `prepare_threshold=None`, T0.4에서 확인 |
| 6 | 채점 프로그램이 key를 찾는 방식과 내 앱의 렌더링이 다름 | 공고에 방식이 없음(확인하지 않았음). Streamlit 판을 고정하고, 배포한 앱에서 브라우저로 key 존재를 확인함 |
| 7 | 앱이 잠들거나 DB가 일시정지됨 | 12시간 방문이 없으면 잠드는 것은 채점자가 깨움(감점 없음). DB는 keepalive로 막음 |
| 8 | 마감 직전 배포 장애 | 첫 배포를 10/31에 함. 최종 점검은 11/2 18:00 목표 |
| 9 | 8명을 넘는 배정에서 탐색이 느림 | 5초 제한과 별도 안내(PRD_step3 4.3절, 완전 탐색). 공고는 8명 이하를 예고함 |
