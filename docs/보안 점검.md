# 배포 전 보안 점검 (진단만, 코드는 고치지 않음)

## 1. 요약

- 점검 대상: 이 저장소의 코드(`streamlit_app.py`, `mp/`, `scripts/`, `schema.sql`, `.github/workflows/keepalive.yml`, `.streamlit/config.toml`)와 `requirements.txt`
- 스택: Streamlit 1.66.1, Streamlit Community Cloud(배포 전), Supabase Postgres(`DATABASE_URL`로 직접 접속), 학번과 비밀번호 로그인(bcrypt)
- **High 1건: 07 최소권한.** 앱이 쓰는 DB 역할이 같은 프로젝트의 다른 앱 테이블 20개까지 지우고 고칠 수 있음. 고칠지는 정하는 대로 따름
- Med 4건: 05 인증과 인가, 09 요청 제한, 11 비밀 값과 교체, 13 감사 기록. 나머지는 Low임
- 의존성은 `pip-audit` 2.10.1을 실제로 돌려 확인함. `requirements.txt`(간접 의존 포함 38개)와 `.venv` 전체 모두 알려진 취약점 없음
- 확인하지 못한 것: 배포한 앱의 응답 머리글(보안 헤더, CSP)과 브라우저 쿠키. 배포 전이라 볼 수 없음
- **결정(2026-10-31, 다른 세션이 전달)**: 07 최소권한(High)은 보류함. 전용 DB 역할을 만들면 새 비밀번호가 생기고 `DATABASE_URL`을 로컬, Streamlit Secrets, GitHub Secrets 3곳에서 바꿔야 하며, 같은 DB를 쓰는 다른 앱과도 맞춰야 하므로 사용자가 아침에 정하기로 함. 나머지 Med와 Low도 이번에는 고치지 않고 진단만 남김. `ADMIN_PASSWORD`는 사용자가 정한 값이라 그대로 둠(05의 12자 미만 지적은 알려진 상태로 남김)

## 2. 진단표

상태: ☑ 구현 / △ 부분 / × 없음 / − 해당없음

| 항목 | 상태 | 위험도 | 수정 방향 |
|---|---|---|---|
| 01. CORS | ☑ | Low | Streamlit 기본값(`server.enableCORS = true`)을 앱이 바꾸지 않음. `.streamlit/config.toml`에 명시해 두고, 배포 뒤 다른 출처에서 웹소켓이 거부되는지 확인 |
| 02. CSRF | ☑ | Low | 기본값 `server.enableXsrfProtection = true`를 쓰고, 상태 변경은 쿠키 인증이 아니라 서버 세션의 웹소켓으로 일어남. 설정에 명시만 하면 됨 |
| 03. XSS + CSP | △ | Low | XSS는 막혀 있음(`unsafe_allow_html`, `st.html`, `st.markdown`에 입력값을 넣는 곳이 없고 `st.text`로만 그림). CSP는 앱이 정하지 못하는 플랫폼 몫이라 배포 뒤 응답 머리글을 확인해야 함 |
| 04. SSRF | ☑ | Low | 밖으로 나가는 호출은 OpenRouter 고정 주소뿐이고 사용자 입력이 주소에 들어가지 않음. 시험용 `MP_AI_BASE_URL`은 배포 환경에 설정하지 않아야 하며(설정하면 API 키가 그 주소로 감), 허용 주소 목록 검사를 넣을 수 있음 |
| 05. AuthN / AuthZ | △ | Med | bcrypt(rounds 10)와 DB의 `is_admin` 재확인은 구현됨. 약한 곳: 학생 비밀번호가 모두 `1234`이고 바꿀 수 없음(공고 2.2절 요구), `ADMIN_PASSWORD`가 12자 미만, 없는 학번과 틀린 비밀번호의 응답 시간이 다름(73ms 대 136ms, 학번 존재 여부 추측 가능), 로그인 만료 없음. 없는 학번에도 더미 bcrypt 검사를 하고, 관리자 비밀번호를 12자 이상으로 하고, rounds 12를 검토 |
| 06. RBAC · 테넌트 | ☑ / − | Low | 역할은 관리자와 학생 2개이고, 투표는 그 팀 팀원만, 지원은 본인만 할 수 있음(시험으로 확인함). 테넌트는 해당없음. 권한 시험을 계속 유지 |
| 07. 최소권한 | △ | **High** | 앱이 `postgres.<프로젝트>` 역할로 접속함. RLS 우회(`BYPASSRLS`)와 역할 생성(`CREATEROLE`) 권한이 있고, 같은 DB의 다른 앱 테이블 20개에 `DELETE` 권한이 있음(접속해서 확인함). 이 접속 주소는 로컬 `.env`, Streamlit Secrets, GitHub Secrets 3곳에 놓임. `tf_mp_` 테이블만 다루는 전용 역할을 만들고(`grant`를 `tf_mp_` 테이블에만), `DATABASE_URL`을 그 역할로 바꾸고, keepalive에는 `select`만 되는 역할을 쓰기 |
| 08. Input + SQLi | △ | Low | SQL은 모두 매개변수로 넣음(`execute` 45곳 중 f-문자열 1곳은 내부 고정값 `update`/`share`). CSV는 형식, 중복, 역할 값을 검증함. 길이 제한이 없음(로그인 입력 `max_chars`, 이름 길이, 업로드 한도 기본 200MB). `max_chars`와 `server.maxUploadSize`를 낮추고, f-문자열 1곳을 고정 문장 2개로 바꾸기 |
| 09. Rate Limit | × | Med | 로그인 시도 제한이 없어 관리자 비밀번호를 여러 세션으로 계속 시도할 수 있음. AI 배정 호출도 간격 제한이 없음(관리자만 가능하나 하루 50회 한도를 소진할 수 있음). 학번별 연속 실패 횟수를 DB에 두고 일정 횟수 뒤 지연이나 잠금, 관리자 계정은 더 엄격하게, AI 배정은 최소 간격 |
| 10. 쿠키 · 세션 | △ | Low | 로그인 상태는 서버 세션(`st.session_state`)에 있고 앱이 쿠키를 만들지 않음. 로그아웃은 세션 키를 지움. 마지막 활동 뒤 자동 로그아웃은 없음. 브라우저 쿠키 목록은 확인하지 않았음. 마지막 활동 뒤 N분이 지나면 로그아웃하는 것을 추가할 수 있음 |
| 11. Secret · Rotation | △ | Med | `.env`는 git이 무시하고, 값 출력 없이 추적 파일을 검사하는 `scripts/check_secrets.py`가 있음. 약한 곳: 교체 절차 문서가 없음, `ADMIN_PASSWORD`는 앱을 다시 시작해야 반영됨, `.env`가 SynologyDrive 동기화 폴더에 있어 클라우드에 복제됨, OpenRouter 키의 사용 한도는 확인하지 않음. 교체 절차(DB 비밀번호를 바꾸고 3곳 갱신)를 문서로 남기고, `.env`를 동기화 폴더 밖에 두고, 키마다 한도를 둠 |
| 12. HTTPS · 보안헤더 | △ | Low | 배포 주소의 HTTPS는 Community Cloud가 제공함(배포 전이라 확인하지 못함). 앱은 응답 머리글을 정하지 못함. DB 연결은 TLS를 실제로 씀(`ssl_in_use`가 참)이나 `DATABASE_URL`에 `sslmode`가 없어 협상 실패 시 평문으로 내려갈 수 있음. `sslmode=require`를 주소에 넣고, 배포 뒤 `curl -I`로 머리글을 확인 |
| 13. Audit Log | △ | Med | AI 호출은 `tf_mp_ai_logs`에 남고 지원과 투표에는 시각이 있음. 로그인 성공과 실패, 관리자 동작(명단 초기화, 모집 마감, 배정 확정)은 누가 했는지 기록이 없음. 명단 초기화는 지원과 투표를 모두 지움. `tf_mp_audit_logs`(시각, 계정, 동작, 결과)를 추가하고 앱 역할에는 `insert`만 허용 |
| 14. 에러 노출 | ☑ | Low | `client.showErrorDetails = "type"`으로 기본값 `full`을 바꿨고, 처리한 예외는 종류만 보임. 키와 접속 정보가 화면에 나오지 않음(시험으로 확인함). 배포 환경에서 이 설정이 적용되는지 확인하고, Streamlit Cloud 로그에는 예외 전문이 남을 수 있음(소유자만 봄) |
| 15. 의존성 취약점 | ☑ | Low | `pip-audit` 2.10.1 실행: `requirements.txt`(간접 의존 포함 38개)와 `.venv` 전체 모두 알려진 취약점 없음. 한계: 직접 의존만 판을 고정하고 잠금 파일이 없어 배포 때 간접 의존 판이 달라질 수 있고, GitHub Actions는 태그(`@v4`, `@v5`)로 고정함. 잠금 파일(해시 포함)을 만들고, 액션을 커밋 해시로 고정하고, 배포 직전에 `pip-audit`을 다시 돌림 |

## 4. 확인하지 못한 것

- 배포한 앱의 응답 머리글, CSP, 쿠키(배포 전)
- OpenRouter 키의 사용 한도 설정(계정 화면을 보지 않음)
- 같은 Supabase 프로젝트의 다른 앱이 이 앱의 `tf_mp_` 테이블을 건드릴 수 있는지(그 앱들의 코드를 보지 않음)
- 취약점 데이터베이스에 아직 없는 취약점(`pip-audit`은 알려진 것만 찾음)
